问题一：fatal error C1083: 无法打开包括文件: “tr1/functional”

如果使用了VS2019，仍然报错，报错内容很长，但是核心只有一句话，找不到<tr1/functional>

C:...\sparsehash\dense_hash_map(106): fatal error C1083: 无法打开包括文件: “tr1/functional”: No such file or directory

该报错源于 google-sparsehash 库。Linux 下的 GCC 编译器支持过时的 C++ TR1 标准，并将头文件放在 tr1/ 目录下；而 Windows 的 MSVC 编译器已经移除了这个目录，直接将相关功能整合进了标准库 <functional> 中。

虽然提示是dense_hash_map的106行，但是我们点进去只发现

#include HASH_FUN_H                 // for hash<>

问题二：bfs_cluster.cpp(86): error C2131: 表达式的计算结果不是常数

原因是Linux和Windows中C++语法差异。Windows上，标准 C++ 不支持这种写法。数组的大小必须在编译时就是一个确定的常量（如 bool visited[1000];），或者必须使用动态内存分配。
